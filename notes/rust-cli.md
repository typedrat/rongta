# Rust CLI dependency choices

The Cargo project lives in `rongta-rs/`; the development flake remains at the
repository root.

The first target is the Android R22 path documented in [r22-path.md](r22-path.md):
Rongta protocol 28 over Bluetooth Classic SPP/RFCOMM. Hardware behavior remains
unverified. The executable supports BlueR-backed `info`, offline discovery/decoding, and
compressed image-data generation; [framing.md](framing.md),
[handshake.md](handshake.md), and [image-data.md](image-data.md) record the
SDK-validated formats.

| Responsibility | Selected crates |
| --- | --- |
| CLI declarations, help, completion support | `usage-rs`, aliased as `usage` |
| BlueZ discovery, pairing, RFCOMM profiles | `bluer` with `bluetoothd` and `rfcomm` |
| Async I/O, timeouts, buffered framing | `tokio`, `tokio-util` with `codec`, `bytes` |
| Binary headers, payloads, packed fields | `deku` |
| Parameterized checksums | `crc` |
| Handshake digest | RustCrypto `md-5` |
| Image decoding and manipulation | `image`, initially PNG and PNM |
| Structured output and fixtures | `serde`, `serde_json` |
| Platform state/config locations | `directories` |
| Typed TOML/environment configuration | `confique`, `toml` |
| Interactive settings menu | `dialoguer` |
| Atomic state replacement | `tempfile`, standard-library file locks |
| Diagnostics | `tracing`, `tracing-subscriber` |
| Packet hex output | `hex` |
| Protocol and application errors | `thiserror`, `anyhow` |
| Property tests and CLI test helpers | `proptest`, Usage's `test` feature |

Deku replaces the initial binrw proposal because its derives directly describe
sub-byte fields, including the message type/subtype nibbles. Complete frames
will be buffered by the Tokio codec before decoding. The codec must bound frame
lengths, tolerate fragmented reads, and handle multiple frames in a read.

Computed lengths should use temporary computed fields where practical. Deku's
`update` attribute requires an explicit `.update()` call; serialization alone
does not update stored length fields. CRC calculation and validation remain
explicit protocol operations using `crc`.

The custom work is the Rongta command definitions, handshake state machine,
raster packing, and compression rules. We will compare against reference bytes
generated by the original SDK before claiming wire compatibility.

Compression is now mapped: Deku's bit vectors handle packing, while a
standard-library heap reproduces native Huffman ties and tree construction.
A generic canonical-Huffman library would not produce the SDK's required tree
traversals and code assignments. No additional dependency was needed.
The traced R22 path does not require the native SDK's AES packet branch.
